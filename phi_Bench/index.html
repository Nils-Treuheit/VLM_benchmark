BENCHMARK METHOD

What each task measures

Fixed samples, prompts, and scoring procedures are shared with the Qwen VLM benchmark.

AI2D · DIAGRAM REASONING

Test split · 100 of 3,088

Each sample contains one diagram, a four-choice question, and four answer options. The prompt requests A, B, C, or D.

Score: exact letter accuracy. Missing or unparsable letters count as incorrect.

TEXTVQA · TEXT IN IMAGES

Validation · 100 of 5,000

Each sample contains one natural image, an open question, and human answer references. The prompt requests the shortest exact text visible in the image.

Score: normalized human-answer consensus, averaged leave-one-reference-out and capped at one.

GRAB-LITE · GRAPH ANALYSIS

Full test split · 500 questions

One graph image per question, balanced across properties, functions, series, transformations, and real figures.

Score: normalized exact-match accuracy, overall and by task group.

GRAB-Lite dataset ↗

Sampling: seed 3407. AI2D and TextVQA use 100 examples each, VQA skill categories use 25 each, and GRAB-Lite uses all 500 examples. The same indices are reused for every model.

Full-suite macro: the unweighted mean of eight task scores. It is a local comparison measure, not an official score from one dataset.

Inference: cached checkpoints run offline, serially, with greedy decoding and one still image per request. Each model uses its processor and chat template; batching is disabled.

Runtime: mean seconds covers generation after preprocessing. Output tokens/second divides generated tokens by that call time. Peak VRAM is process-local.

Answer handling: open answers are normalized by the shared scorers. Parse failures count as incorrect. Phi-3 and Phi-4 compatibility patches stay within the Phi adapter and appear in checkpoint details.

Memory tiers: 12 and 16 GiB candidates use the maximum process-local peak across all eight tasks at the listed test context. These are not constrained-memory reruns or estimates for shorter contexts.
